# Sunday Suite — website (sundaysuite.app)

The marketing/landing site for the **Sunday Suite** family of church-tech products.
Static, bilingual (English primary, Norwegian secondary), deployed on **Cloudflare Pages**.

- **Live:** https://sundaysuite.app  (English) · https://sundaysuite.app/no/ (Norwegian)
- **Pages preview:** https://sundaysuite.pages.dev
- **Contact:** dev@sundaysuite.app

## What's here

plus a **community toolbox** (11 free web tools with a dedicated landing page),

## Architecture

Everything is generated by one script — **`build.py`** — into static HTML. There is
**no Node build step**; `build.py` is plain Python 3 (standard library only).

```
build.py                  ← single source of truth for ALL page content (EN + NO)
index.html                ← EN home (generated)
toolbox.html              ← EN toolbox landing page (generated; NO: no/verktoykasse.html)
build.html                ← EN "Build with us" page (generated; NO: no/bygg.html)
apps/*.html               ← EN product pages (generated)
legal/{terms,privacy}.html← EN legal (generated)
help/*.html               ← EN help guides (generated; NO: no/hjelp/*.html)
no/…                      ← Norwegian mirror of the above (generated)
assets/
  site.css                ← shared stylesheet (hand-edited, NOT generated)
  site.js                 ← shared nav + scroll-reveal + version badge (hand-edited)
  favicon.svg             ← suite mark (gold cross on ink tile)
  logos/{slug}.svg        ← per-product app-icon tiles
sitemap.xml               ← generated (50 clean URLs with hreflang alternates)
robots.txt                ← generated (allows all, points at the sitemap)
_redirects                ← generated (301s for removed help guides, REMOVED_HELP)
functions/
  _middleware.js          ← Pages Function: 301-redirects sundayrec.com → /apps/sundayrec
  download/
    _lib.js               ← shared: update-ring feeds, semver guard, handler factories
    {sundayrec,sundayscreen,sundaystage,sundaysync,sundayedit}/
      [platform].js       ← /download/<app>/{mac,windows} → newest installer (302)
      version.js          ← /download/<app>/version → {"version","pub_date"} JSON
.assetsignore             ← keeps build.py/docs out of the deployed upload
```

Every page carries a canonical URL plus `en`/`no`/`x-default` hreflang
alternates (clean, extensionless URLs — `page_pairs()` in `build.py` is the
single list driving both the head tags and the sitemap).

### Editing content

1. Edit the data dictionaries in **`build.py`**: `STATUS` (product maturity),
   `HOME`, `CARD`, `APP`/`APPDATA` (product pages — an entry with a `repo` key
   gets download buttons; one with `url` gets an "Open …" button), `RING_APPS` +
   `REPOS` + `BUILDPAGE` (the build page), `TOOLS` + `TBPAGE` (toolbox),
   `HELPDOC` + `HELP_ORDER` + `REMOVED_HELP` + `HELP_INDEX` (help section),
   `CH` chrome strings, and the legal `terms_*/privacy_*` functions.
   Each holds an `"en"` and a `"no"` variant — keep them in sync.
2. Regenerate:
   ```
   python3 build.py
   ```
   This rewrites all 50 HTML pages (25 EN, 25 NO: home + toolbox + build + 12
   products + 2 legal + help index + 7 guides per language) plus sitemap.xml,
   robots.txt and _redirects.
3. Styling lives in `assets/site.css` (edit directly — not generated).

### Download redirectors

`/download/<app>/mac` and `/download/<app>/windows` 302-redirect to the newest
installer for sundayrec, sundayscreen, sundaystage, sundaysync and sundayedit.
Version sources (see `functions/download/_lib.js`):

- **Update rings** (`updates.sundaysuite.app/v1/update/<app>/<ring>`, cached
  ~15 min): the default channel serves the stable ring, falling through to the
  beta ring when nothing is promoted on stable (204). `?channel=beta` serves the
  **semver-highest of both rings** — a beta link can never hand out something
  older than stable (the rings are promoted independently and beta can lag).
- **GitHub `releases/latest/download/latest.json`** as fallback — and the only
  source for sundayedit (not on the rings; universal-mac assets, repo on the
  personal account).

Any failure falls back to the GitHub releases page — never a 500.
`/download/<app>/version` serves `{version, pub_date}` for the badge on the
product pages (`[data-app-version]` in `site.js`). New releases need **no site
redeploy**.

### sundayrec.com redirect

The old sundayrec.com site was an Astro app deployed as a **Cloudflare Worker**
(`sundayrec-website`) with a custom domain on the apex. To retire it:

1. Attached `sundayrec.com` + `www` as custom domains on the `sundaysuite` Pages project.
2. **Detached** the Worker custom domain (the Worker script still exists, just no longer serves).
3. Repointed DNS (apex + www) to `sundaysuite.pages.dev`, **keeping the MX records** (email intact).
4. `functions/_middleware.js` 301-redirects any request whose host is `sundayrec.com`
   or `www.sundayrec.com` to `https://sundaysuite.app/apps/sundayrec`; all other hosts
   pass through untouched.

> **Gotcha:** Cloudflare Pages `_redirects` does **not** reliably match on hostname —
> use a Pages Function (`_middleware.js`) for host-based redirects, as done here.

### DNS verification gotcha

When checking DNS from a sandboxed shell, plain `dig` (port 53) gave false-empty
answers and negative caching. Use **DoH over HTTPS** for ground truth, e.g.
`curl "https://dns.google/resolve?name=sundaysuite.app&type=A"`, and `curl --resolve`
to test HTTPS before public DNS settles.
