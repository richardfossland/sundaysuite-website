# sundaysuite.app

A plain site for getting hold of the Sunday Suite programs. Static HTML,
Norwegian at the root and English under `/en/`, deployed on Cloudflare Pages.

- Live: https://sundaysuite.app (Norwegian) · https://sundaysuite.app/en/ (English)
- Contact: dev@sundaysuite.app

## What is on it

- **Front page** — SundayRec (the only downloadable beta), the web programs
  (open in the browser), the programs in development, a short support note
  with Vipps, and a collapsed list of programs that are not a priority.
- **One short page per program** (23) under `/apps/<slug>`.
- **Terms and privacy** under `/legal/`.
- **404 page**.

Status lives in one place, the `group` field of each entry in `PROGRAMS` in
`build.py`:

| group | shown as | action |
|---|---|---|
| `download` | Beta | download buttons (SundayRec) |
| `web` | no label | “Open” link to the app |
| `dev` | In development | quiet test-build link where `testbuild` is set, source link where `repo` is set |

`parked: True` moves a program out of the main lists into a collapsed
“not a priority” section at the bottom of the front page (currently Info,
Booking, Welcome, Plan, Song and Paper). It keeps its page and its group's action.

## Building

Everything is generated by `build.py` (Python 3, standard library only). Legal
text lives in `legal.py`. Stylesheet and the small version script are hand-written.

```
python3 build.py && python3 check_links.py
```

`check_links.py` fails if a page is missing, a stray old page is left behind,
a relative link is broken, an absolute path other than `/download/` appears, or
retired copy comes back.

```
build.py            program data, UI text, page templates, sitemap, _redirects
legal.py            terms + privacy text (EN + NO)
check_links.py      quality gate
index.html          generated (NO)      en/index.html      generated (EN)
apps/*.html         generated (NO)      en/apps/*.html     generated (EN)
legal/*.html        generated (NO)      en/legal/*.html    generated (EN)
404.html            generated, bilingual, absolute links
sitemap.xml, robots.txt, _redirects     generated
assets/site.css     hand-written
assets/site.js      shows the newest SundayRec version next to the download links
assets/logos/       app icons for the 12 core programs
assets/vipps-qr.png official Vipps QR for #24288
functions/          Pages Functions (not generated)
```

## Downloads

Download links point at `/download/<app>/{mac,windows}`, Pages Functions in
`functions/download/` that 302 to the newest installer. The version comes from
the suite's update rings (`updates.sundaysuite.app`), with GitHub's
`latest.json` as a fallback; they never return a 500. New releases need no site
redeploy. `/download/<app>/version` returns `{version, pub_date}`.

Endpoints exist for sundayrec, sundayscreen, sundaystage, sundayedit and
sundaysync. Only SundayRec is linked from the front page; the other four are
linked quietly as test builds on their program pages.

## Old addresses

`_redirects` (generated from `REDIRECTS` in `build.py`) sends the old
Norwegian `/no/...` pages to the root, and the retired toolbox, build-with-us
and help pages to the front page. `/apps/<slug>` and `/legal/*` kept their
addresses. `functions/_middleware.js` 301-redirects the retired sundayrec.com
domain to `/apps/sundayrec`.
