# Sunday Suite — website (sundaysuite.app)

The marketing/landing site for the **Sunday Suite** family of church-tech products.
Static, bilingual (English primary, Norwegian secondary), deployed on **Cloudflare Pages**.

- **Live:** https://sundaysuite.app  (English) · https://sundaysuite.app/no/ (Norwegian)
- **Pages preview:** https://sundaysuite.pages.dev
- **Contact:** dev@sundaysuite.app

## Architecture

Everything is generated by one script — **`build.py`** — into static HTML. There is
**no Node build step**; `build.py` is plain Python 3 (standard library only).

```
build.py                  ← single source of truth for ALL page content (EN + NO)
index.html                ← EN home (generated)
apps/*.html               ← EN product pages (generated)
legal/{terms,privacy}.html← EN legal (generated)
no/…                      ← Norwegian mirror of the above (generated)
assets/
  site.css                ← shared stylesheet (hand-edited, NOT generated)
  site.js                 ← shared nav + scroll-reveal (hand-edited)
  favicon.svg             ← suite mark (gold cross on ink tile)
  logos/{slug}.svg        ← per-product app-icon tiles
functions/_middleware.js  ← Pages Function: 301-redirects sundayrec.com → /apps/sundayrec
.assetsignore             ← keeps build.py/docs out of the deployed upload
```

### Editing content

1. Edit the data dictionaries in **`build.py`** (`HOME`, `CARD`, `APP`, `APPDATA`,
   `CH` chrome strings, and the legal `terms_*/privacy_*` functions). Each holds an
   `"en"` and a `"no"` variant — keep them in sync.
2. Regenerate:
   ```
   python3 build.py
   ```
   This rewrites all 20 HTML pages (10 EN at the root, 10 NO under `/no/`).
3. Styling lives in `assets/site.css` (edit directly — not generated).

### sundayrec.com redirect

The old sundayrec.com site was an Astro app deployed as a **Cloudflare Worker**
(`sundayrec-website`) with a custom domain on the apex. To retire it:

1. Attached `sundayrec.com` + `www` as custom domains on the `sundaysuite` Pages project.
2. **Detached** the Worker custom domain (the Worker script still exists, just no longer serves).
3. Repointed DNS (apex + www) to `sundaysuite.pages.dev`, **keeping the MX records** (email intact).
4. `functions/_middleware.js` 301-redirects any request whose host is `sundayrec.com`
   or `www.sundayrec.com` to `https://sundaysuite.app/apps/sundayrec`; all other hosts
   pass through untouched.

> **Gotcha:** Cloudflare Pages `_redirects` does **not** reliably match on hostname —
> use a Pages Function (`_middleware.js`) for host-based redirects, as done here.

### DNS verification gotcha

When checking DNS from a sandboxed shell, plain `dig` (port 53) gave false-empty
answers and negative caching. Use **DoH over HTTPS** for ground truth, e.g.
`curl "https://dns.google/resolve?name=sundaysuite.app&type=A"`, and `curl --resolve`
to test HTTPS before public DNS settles.
